# larkflow 既有设计简化记录

> 状态：2026-08-01 已完成。本文件记录既有产品设计的范围收敛，不证明市场需求或当前实现。

## 证据等级

- 证据等级：内部产品规格，不是用户研究、商业验证或实现证据。
- 使用方法：以现有 AIREADME 为底稿，保留能形成最小闭环的规则，一体化办公平台专属对象、跨服务拓扑和后续能力不直接复制。
- 项目约束：larkflow 复用飞书，不建设独立的项目、IM、搜索、知识库和应用市场全套平台。

## 简化基线

当前设计保留：

1. 实例草稿、确认启动和丢弃。
2. 无模板实例。
3. 模板锁定及实例锁定规则。
4. 运行中实例编辑及二次确认。
5. 节点重启和完整重启。
6. 默认节点评价、Agent 自动重跑和 Human 打回重做。
7. 所有节点与飞书责任入口 1:1 映射。
8. Human、Agent、Tool 节点路由。
9. 实例状态、节点状态和进度。

子 DAG 和跨服务事件总线放在后续版本。简化 MVP 以这个范围分界，不把既有设计中的所有设想一次纳入。

## 冲突消解

| 既有设计口径 | larkflow 决定 | 原因 |
|---|---|---|
| 独立 Project 与顶层 DAG Instance 绑定 | 不建设独立 Project 聚合；Instance 保存最小目标、Owner、成员和材料引用 | larkflow 复用飞书，不复制完整项目平台 |
| Human 与 Agent 节点都生成项目待办 | 所有节点保留唯一人类 Owner；自动节点由中央执行器运行，责任入口向 Owner 可见 | 保留人类责任边界 |
| 默认五维百分制评分，Agent 多次自动重跑 | MVP 改成 `pass/fail + evidence + suggestion`，只允许有限自动重试 | 先验证流程闭环，不先建设评分产品 |
| 子 DAG 有完整模型 | MVP 不实现子 DAG；Later 若实现，最多 3 层并复用普通 Instance 生命周期 | 控制首版范围 |
| 使用跨服务事件总线 | MVP 使用 PostgreSQL 事务和 outbox 驱动飞书投影 | 模块化单体先行，保留未来拆分接口 |
| 模板匹配依赖检索，允许自然语言变更 | MVP 接受显式模板或结构化无模板草稿；自然语言只生成预览，不直接执行 | 消除外部依赖，保留确认门 |
| 模板有草稿、启用、禁用、删除和版本快照 | 原样保留，删除使用逻辑终态 | 状态足够形成闭环 |
| locked 包含结构锁定和预设值锁定 | MVP 只保留模板版本级布尔 `locked` | 不做逐字段锁定 |
| 运行中只改未来并需预览确认 | 原样保留，使用 `graph_revision` 防止过期预览 | 安全编辑的最小必要机制 |
| 节点重启影响自身和全部可达下游并保留历史 | 原样保留，用 Attempt 记录轮次，不画业务回边 | 与当前原型的选择性重算经验兼容 |

## 简化 MVP

### 保留

- Template 可选，允许从模板或无模板结构化草稿开始。
- Instance 必须先 `draft`，由人明确确认后才能 `running`。
- 模板版本不可变，实例保存完整图快照。
- 模板生命周期为 `draft / enabled / disabled / deleted`。
- Instance 和 Node 使用最小状态机。
- 每个节点有唯一人类 Owner，执行器为 `human / agent / tool`。
- 每个节点投影一个飞书责任入口，自动节点完成后同步结果，失败时由 Owner 接管。
- 运行中只编辑未开始区域，预览和确认分离。
- 节点重启重置自身和全部下游，保留历史轮次。
- 简单质量判定、进度、幂等、审计和投影对账。

### 简化

- 不建立独立 Project 聚合，Instance 自带最小项目元数据。
- 不做五维百分制，使用可解释的通过或失败结果。
- 不做检索式模板匹配，先显式选择模板或创建无模板草稿。
- 不做专用 DAG 画布，参与人从飞书任务和卡片进入。
- 不拆微服务，不引入事件总线；中央服务先是模块化单体。

## MVP 功能验收

1. 用户可以从启用模板或结构化无模板定义创建草稿，草稿不会执行或创建飞书任务。
2. 用户确认后同一 Instance 进入 running，并为所有节点建立唯一 Owner 和飞书投影。
3. Human 节点由 Owner 完成；Agent 或 Tool 节点自动执行，但异常、接管和最终责任仍回到 Owner。
4. 服务重启后可以从 PostgreSQL 恢复当前状态，并重建缺失投影。
5. 项目 Owner 可以预览并确认只影响未来节点的编辑，过期 revision 必须拒绝。
6. 节点重启可以预览影响范围，确认后重置该节点及全部可达下游，历史 Attempt 保持只读。
7. 完成、失败、暂停、取消和丢弃遵守状态机，所有关键变化可审计。

## 设计结论

这套 MVP 是对既有设计所做的范围简化，不是已经验证的市场 MVP。它允许项目继续做产品和工程设计，但所有市场规模、使用频率、降本比例和付费意愿仍保持未知。
