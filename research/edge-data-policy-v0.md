# Personal Agent Edge 数据政策 v0.1

状态：开发验收基线

适用范围：Personal Agent Edge Proof v0 在员工本人主动启动的前台会话中，从一个明确选择的本机工作区读取必要内容，并将中央输入、提示和必要工作区内容发送给员工本人使用的模型服务商。

本政策不是生产放行，也不替代供应商合同、隐私评估、法务意见或组织安全制度。

## 1. 默认规则

1. 默认拒绝。只有 `synthetic` 和 `public` 可以进入当前 Edge Proof。
2. 每次 `run-once` 或 `serve` 都必须显式声明 `--data-classification`，并提供 `--allow-model-egress`。
3. `doctor --workspace` 必须在当前 Mac、当前 Codex 版本和目标工作区通过正反隔离探针。
4. 工作区分类发生变化，或任务需要读取工作区外内容时，必须停止当前会话并重新评估。
5. Edge 不提供隐藏后台常驻，不安装操作系统守护进程，不通过飞书或 `lark-cli` 传输工作区内容。

## 2. 数据分级

| 分级 | 例子 | 当前策略 |
| --- | --- | --- |
| `synthetic` | 人工构造的代码、测试夹具、虚构业务材料 | 允许 |
| `public` | 已公开的开源仓库、公开文档、公开标准 | 允许 |
| `internal` | 未公开代码、内部设计、内部运营材料 | 拒绝 |
| `confidential` | 客户材料、商业秘密、合同、财务与人事信息 | 拒绝 |
| `restricted` | 凭据、私钥、令牌、身份信息、受监管数据 | 拒绝 |

同一工作区存在多个分级时，按最高分级处理。无法判断时按 `internal` 处理，因此当前拒绝。

## 3. 技术强制项

- CLI 只接受 `synthetic` 或 `public`，其他值在读取设备凭据和调用模型前失败。
- Codex 子进程采用目录级只读 permission Profile，根目录默认拒绝，只开放所选工作区，并额外拒绝常见凭据、Agent 配置、私钥和证书路径。
- 命令网络、网页搜索、浏览器、Computer Use、应用和图片生成关闭。
- 执行结果记录政策版本、数据分级、目录只读、敏感路径拒绝和模型外发确认。
- 设备凭据使用 macOS Keychain，元数据文件不保存设备密钥。
- 中央节点按人员、租户、节点 Owner、capability、Attempt 和短时租约重新授权，不信任员工端自报身份。

这些机制降低误用概率，但不能证明模型服务商没有接收工作区内容，也不能阻止员工把敏感文件误放进已批准工作区。

## 4. 人员责任

员工：确认工作区分级，运行 `doctor`，只在可见前台会话中启动 Edge，发现不应外发的内容立即停止。

中央节点管理员：只向已确认人员签发一次性配对码，保持设备可撤销，审查异常租约、失败与重复执行，验收结束后撤销测试设备。

仓库维护者：固定员工端模块白名单、依赖哈希、SBOM 和构建证明，保持安装、升级、回滚、卸载与凭据边界可验证。

## 5. 日志、保留与事件响应

- 员工端只向标准输出写结构化运行状态，不应输出设备密钥、配对码或工作区正文。
- 节点结果和追加型审计由中央工作流保存。具体保留周期尚未形成生产制度，因此当前只允许开发测试数据。
- 模型服务商的训练、保留和管理员控制取决于员工使用的账户与服务条款，当前系统不能代替组织核验。
- 发现误分类、凭据暴露、越权读取或异常外发时，立即停止 Edge，撤销中央设备，保存脱敏审计，轮换可能暴露的凭据，并在原因查明前暂停该工作区。

## 6. 放宽条件

将 `internal` 加入允许列表前，至少需要完成：组织批准的模型服务商与账户边界、数据处理与保留条款、管理员可执行的事件响应流程、代表性内部材料测试、全新员工 Mac 验收和明确的责任人。

Developer ID 签名与公证属于分发信任链，不改变数据分级结论。本轮按产品决策暂不处理。
