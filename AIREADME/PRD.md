# PRD · larkflow（飞流）

> 状态：Cloud-first Target + Paused Edge Proof · 既有设计简化版 · 2026-08-14
>
> 证据边界：本 PRD 是既有设计的范围简化，不代表市场需求已经验证。

## 1. Summary

larkflow 是基于飞书的企业协作与 Agent 工作流控制平面。用户从启用模板、自然语言引导或结构化定义创建项目工作区，按需引用企业共享资料或上传项目材料，系统生成 DAG 草稿，确认后启动实例。每个节点保留唯一人类 Owner，并按依赖调度 Human、Agent 或 Tool 执行器。中央服务保存版本、状态、Attempt、权限和审计；飞书承载责任入口、通知和材料。

MVP 只实现单个顶层 DAG，不实现子 DAG、独立 Project 聚合和完整知识平台。一个项目工作区先映射为一个 Workflow Instance 加项目级上传件。Personal Agent Edge 已暂停，不进入 MVP 默认交付承诺。

## 2. 角色

| 角色 | 主要责任 |
|---|---|
| 项目 Owner | 创建、确认、查看、编辑、暂停、取消或重启实例 |
| 节点 Owner | 对节点结果负责，处理人工任务或自动执行异常 |
| 流程管理员 | 创建模板版本，启用、禁用、逻辑删除和锁定模板 |
| 系统执行器 | 运行 Agent 或 Tool 节点，不成为责任主体 |

产品范围变化由 Product owner 决策。模板启用和实例高影响操作必须由服务端鉴权并记录审计。

## 3. 问题

多人流程通常分散在群聊、任务和文档中。流程发起后，责任、依赖、变更影响和重做范围容易失真。自动执行器虽然能完成部分工作，但不能替代人的组织责任，也不能成为跨人流程的唯一状态源。

现有仓库验证了部分飞书投影、打回、幂等和恢复机制，但其 LangGraph + SQLite 模型仍是 legacy 原型。目标实现差距见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 4. MVP 目标

完成一个理由明确、责任清晰、可受控变更和可恢复的单层 DAG 闭环。

### 4.1 草稿与启动

- 用户可以选择一个 `enabled` 模板，也可以通过自然语言引导或结构化高级入口提交无模板定义。
- 自然语言生成的图只是候选。服务端必须保留用户原始输入、限制可生成的执行器和 Owner 角色，并对完整 Snapshot 重新校验。
- 自然语言候选不能把“尚未知道必要输入”直接压缩成生成节点。包含 Agent 时，至少先有一个普通 Human 根节点补全并确认必要事实；每条依赖都必须在下游 `work.inputs` 中被明确消费。对于旅游规划等已知高风险场景，服务端还要确定性检查出发地、日期、人数、预算，以及景点和交通两类独立研究交付物，不能只依赖提示词自律。
- 系统先创建 `draft`，展示节点、依赖、Owner、执行器和验收条件。
- 草稿不得执行或创建飞书任务。
- 用户必须明确选择确认启动或丢弃。
- 启动时冻结模板版本、图、输入和责任绑定快照。

### 4.2 模板

- 生命周期为 `draft / enabled / disabled / deleted`，`deleted` 是逻辑终态。
- 同一模板的新修改生成新的不可变版本。
- `locked` 只表示该模板版本不允许实例级结构修改，不做字段级锁。
- 已有实例不因模板后续版本变化而改变。

### 4.3 节点与责任

- 每个节点必须绑定一个唯一人类 Owner。
- `executor` 为 `human / agent / tool`。
- 每个节点必须声明至少一项交付物。新建或生成节点的交付物使用有界字段合同，至少包含 `id / type / label / required`；完成节点时必须提交满足合同的结果，下游只消费已提交的上游结果。没有独立交付物的动作不单独成为节点。
- 普通 Human 节点可由当前 Owner 在员工工作台填写并提交，也保留飞书 Task 作为责任投影；需要明确接受或退回的 Human 节点可以在工作台或版本绑定的飞书决定卡完成，两条入口调用同一服务端领域命令。
- 普通 Human 节点若声明必填交付物，工作台必须按字段类型渲染表单并由服务端再次校验。飞书原生 Task 只承担责任提醒和工作台入口，勾选完成不能代替提交必填交付物，也不能推进中央节点。
- Agent 或 Tool 节点由中央执行器自动运行，结果同步给 Owner；失败、超限或需要判断时由 Owner 接管。
- 来源约束型 Agent 结果必须区分来源事实、推断和开放问题，并引用服务端登记的稳定事实或问题 ID。确定性 Tool 只校验结构、引用和来源一致性，事实真伪与业务适用性仍由 Human Owner 判断。
- 当工作目标是形成决定而不是整理材料时，必须使用独立的来源约束型决策结果。它只给出一项优先级，逐一回答登记的全部决策问题，给出 3 到 5 条完成标准、不做事项及重新评估条件，并把这些内容标记为来源支持的建议推断。材料复核结果不得被误当成决策结果。
- 需要接受或退回的 Human 节点必须保留明确决定入口和飞书决定卡投影，普通飞书 Task 完成状态不能代替接受决定。
- 每个节点保留一个可对账的飞书任务或等价责任投影。

### 4.4 状态与进度

- 实例至少支持 `draft / running / paused / done / failed / canceled / discarded`。
- 节点至少支持 `pending / ready / running / waiting_human / done / failed / canceled`。
- 只有依赖满足的节点可以进入 `ready`。
- 聚合进度来自中央状态，不以飞书客户端状态反推。
- Instance Owner 点击飞书应用后应进入“我的工作台”，查看本人流程列表、DAG、历史 Attempt、审计与服务端派生的待处理提示；节点参与者还能看到分配给自己的 Human Task 和决定节点，但不能读取其他 Owner 的完整实例。飞书客户端内优先复用应用 OAuth 登录，外部浏览器进入同一授权链路；服务端必须从飞书身份显式映射 tenant 与 person，客户端不得声明 Owner。确认草稿、暂停和继续可以由工作台调用现有领域服务直接执行；取消和重启必须先展示影响预览，再由 Owner 明确确认。普通 Human Task 可在页面提交或转交，明确决定可在页面接受或填写意见后退回。工作台不得建立第二套状态，也不得把浏览器提交的身份、版本、任务责任人或节点状态当成可信事实。

### 4.5 运行中编辑

- 只能编辑尚未开始的节点及其边。
- 服务端先返回变更预览、影响节点和新的 `graph_revision` 候选。
- 用户确认时必须携带预览所基于的 revision；过期请求拒绝。
- 变更只作用于 Instance，不反写 Template。
- 第一版受控 DAG 画板允许 Owner 增加、修改或删除未来区域节点，并从选中节点发起返工。浏览器只提交有界操作或预览 ID，服务端重新计算权限、冻结线、完整 DAG、Owner、版本和影响集合。
- 普通用户增加节点时不填写内部标识，服务端根据执行器生成唯一稳定 key。用户可选择“插入到这些节点之前”，服务端在同一 GraphEditPreview 中增加节点、重连目标节点依赖，并同步重写其 `dependencies.<node_key>` 输入引用。
- 节点拖动只改变当前浏览器保存的个人布局，不改变依赖、调度或审计。恢复自动布局不会写入领域数据。
- 当前版本同时支持表单选择依赖、节点端点拖拽连边和选中连线断开，但不支持任意图形、多人实时协同或通用自由白板。

### 4.6 重启与质量

- 节点重启先预览目标节点及所有可达下游。
- 确认后为受影响节点创建新 Attempt，并保留旧 Attempt、交付物和审计。
- 完整重启按同一规则作用于全部节点。
- MVP 质量结果为 `pass/fail + evidence + suggestion`。
- Agent 可以按服务配置有限自动重试；Human 节点由 Owner 明确重做。
- Human Owner 退回自动结果时必须填写不超过 1000 字的具体意见。当前 Human Attempt 与 Instance 进入失败终态，意见写入结果、质量证据和追加型审计，旧 Attempt、结果和审计保持只读。
- 后续修订通过既有节点重启创建新 Attempt。若目标与失败决定的 `reject_target` 一致，退回意见只进入该目标新 Attempt 的 `rework_feedback`；接受路径忽略额外意见，完整实例重启不隐式继承局部意见。

### 4.7 飞书与恢复

- 飞书卡片、任务、消息和文档是投影，不是业务真相源。
- 必须填写交付物的 Human Task 描述要明确提示不能只勾选飞书任务，并提供只包含受控 `action / instance / node` 参数的工作台深链。服务端只对白名单主页查询返回页面，其余静态资源查询继续拒绝。
- 每张包含按钮、选择器或提交动作的卡片，点击后的首个可见状态必须尽快发生变化。服务端先耐久记录动作，再把原卡片替换为无按钮的“处理中”，最终替换为无按钮的成功或拒绝状态；视觉反馈不代表授权已通过。
- 外部写使用稳定幂等键，投影记录可对账和重建。
- 服务重启后从 PostgreSQL 恢复实例并继续调度。
- 所有关键动作记录 actor、时间、来源、前后状态、instance、node、attempt 和 revision。

### 4.8 云端 Agent 与知识上下文

- 首版知识来源只有两类：管理员明确发布为当前企业全员可用的共享资料，以及用户上传到当前项目工作区的资料。
- 企业共享资料不得绕过源系统仍存在的部门或个人 ACL。无法得到明确全企业发布清单时，MVP 只启用项目上传。
- 项目上传默认只对当前 Instance 的合法参与者开放，并由服务端按 actor、节点、Attempt、数据分类和模型外发政策进一步缩小范围。
- `PlannerRuntime` 只生成候选 DAG、校验报告、规划证据和用量。候选必须由 larkflow 的确定性校验器复验，并由 larkflow 写成 `draft`；Planner 不能直接写数据库或启动流程。
- `AgentRuntime` 一次只执行一个节点的一个 Attempt。它可以通过短时能力信封调用知识检索、上传件读取、组织与模板查询、能力查询、DAG 校验、批评和调度模拟等只读工具。
- Agent Attempt 内部首版不开放业务写工具。飞书写入、外部系统变更和其他副作用必须继续建模为 DAG 上显式 Tool 节点，保留唯一 Human Owner、幂等键和审计。
- 知识范围、工具能力和业务状态转换分别授权。向量索引、模型提示词、Pi session、DSH 日志或运行时 checkpoint 都不是授权或业务真相。
- 每次 Attempt 记录实际 runtime、provider、版本、模型、工具清单、知识范围、数据分类、外发策略、预算与产物摘要。需要切换 runtime 或 provider 时创建新 Attempt，不在当前 Attempt 内静默切换。
- Pi、DeepSeek Harness 和 LangGraph 都只允许位于稳定端口之后。PTC 只可在隔离的 Planner 中组合只读工具，Subagent 只属于当前 Attempt，不能成为业务节点、Owner 或 Human Gate。

### 4.9 Personal Agent Edge Proof v0

> 状态：Paused。下列内容记录已经实现的历史 Proof，不属于当前开发主线或默认部署。

- Edge 不是飞书机器人，也不使用员工电脑上的 `lark-cli` 与中央节点通信；它只通过中央私有 HTTPS API 领取工作。
- 管理员只能为指定 tenant 和 person 签发短时、一次性配对码；设备凭据可列出、撤销且服务端只保存哈希。
- v0 唯一能力是 `personal.readonly`。设备只能领取 Owner 等于配对人员、执行器为 Agent 且显式声明该 kind 的节点。
- 用户必须在本人电脑显式选择工作区，可以手工执行一次 `run-once`，也可以主动启动保持可见的前台 `serve` 会话。一个 `serve` 会话只使用启动时固定的单工作区和既有 `personal.readonly` capability，不注册操作系统后台服务。每次执行前必须通过目录级只读正反探针，并由用户为当前前台会话显式确认模型数据外发；未确认时不得加载设备凭据、领取中央工作或调用模型。Codex permission Profile 只允许读取所选工作区并排除环境文件、Agent 配置、证书和常见私钥名，Edge 凭据、Target DSN 和飞书应用凭据不传给子进程。完成任务所需的工作区内容仍可能发送给模型服务商。
- `edge-data-v0.1` 默认拒绝数据外发。当前只允许用户为本次会话显式声明 `synthetic` 或 `public`；`internal`、`confidential` 和 `restricted` 不可领取，也没有客户端绕过参数。数据分类、目录隔离和模型外发确认必须共同成立，执行结果保存不含正文的策略摘要。
- 本机卸载必须先确认 manager 读取到的精确绝对前缀，只能删除受管 release、`current / previous` 与稳定命令。卸载不得删除 Keychain、设备元数据或把设备标成已撤销；中央撤销必须独立完成，并优先于本机清理。
- 长任务通过当前 Attempt、节点版本、Worker、token 和过期时间续租；撤销设备后不能续租或回传，迟到结果不能改变状态。
- 本机执行器异常不直接把业务流程判为失败，中央等待租约过期后允许其他合法设备接管。
- v0 不提供操作系统后台常驻、自动启动、任意 shell、文件写入、飞书操作、Human gate 代答、通用能力安装或公网直连 Gateway。

## 5. 体验原则

- 参与人优先从飞书任务和卡片进入，不要求理解 DAG 实现细节。
- 每个责任入口都显示“谁负责、等待什么、如何完成、如何验收”。
- 用户点击可操作卡片后不应面对静止界面；处理中、成功和拒绝都必须在原卡片上可见，重复点击不得重复执行领域动作。
- 生成、编辑和重启都先预览后确认。
- MVP 的结构真相仍是服务端 DAG。专用画板只是受控操作面，不拥有独立状态机，也不能绕过预览确认。

## 6. 功能验收

1. 启用模板和无模板定义都能创建不执行的草稿。
2. 确认启动后，同一实例进入运行态，所有节点都有唯一 Owner 和飞书投影。
3. Human、Agent、Tool 节点按统一依赖和状态规则推进。
4. 服务重启后状态一致，缺失投影可以重建，重复事件无副作用。
5. 未来区域编辑必须通过预览、确认和 revision 校验。
6. 节点或完整重启正确重置下游，并完整保留历史 Attempt。
7. 暂停、恢复、完成、失败、取消和丢弃符合状态机，关键变化可审计。
8. 来源约束型结果中的事实、推断和开放问题可确定性对账，但系统不把结构检查描述为事实核验。
9. 接受或退回只能由当前 Human Owner 在版本绑定的工作台或飞书决定入口提交。退回必须携带非空且不超过 1000 字的意见，并在目标节点重启后进入其新 Attempt；旧入口、非 Owner 和普通 Task 完成都不能绕过决定。
10. Instance Owner 可以从中央控制台查看本人流程、DAG、历史 Attempt 和审计，并执行服务端允许的受控流程操作；不存在与非 Owner 资源不可区分，所有写操作必须重新经过服务端 tenant、Owner、当前状态和版本校验。
11. 控制台可以从最近的 Owner 实例派生失败恢复、本人 Human 待办、暂停继续和草稿确认提示。提示不得保存独立业务状态、暴露协作者身份或原始错误。确认草稿、暂停与继续可以直接执行；取消与节点或完整实例重启必须先预览影响，再显式确认，并保留旧 Attempt、结果与审计。按钮必须在发起请求前立即进入处理中状态。
12. 员工工作台登录不得依赖服务器或员工电脑上的 `lark-cli` 用户登录。服务端完成 OAuth code 交换、飞书 tenant 校验和 person 映射后，只向浏览器发放不透明的 HttpOnly 会话；飞书用户 token 不进入前端存储或流程数据。已完成会话只在 PostgreSQL 保存凭据摘要与服务端主体，并能跨 Console 重启继续使用。
13. 最小管理员能力只能由服务端 `tenant + person` allowlist 授权。页面只读展示当前企业的流程状态、migration 与耐久队列聚合；有效会话列表只返回 `you / member` 关系、安全不透明 ID、创建与过期时间，不返回人员 ID、凭据、原始错误、payload 或 claim。当前会话只能注销，其他会话必须先创建五分钟有效的耐久预览，再显式确认撤销；确认必须原子删除会话、追加不可变审计并支持幂等回放。普通成员与不存在接口必须得到相同 404。allowlist、队列、配置和管理员级流程处置仍保持后置；Owner 对本人实例的受控操作不授予管理员权限。
14. 来源约束型决策必须恰好包含一项优先级并回答全部登记 Q。确定性检查应拒绝缺失回答、重复回答、少于 3 条或多于 5 条完成标准、缺少重新评估条件、未覆盖的 F 引用和来源 URL 漂移；通过仍不代表建议在业务上正确。
15. Human Task 的当前负责人可以在工作台读取有界上下文。普通任务可以提交结果，或把运行时责任转交给同一 tenant 内、中央应用可见且活跃的成员；决定节点可以接受，或填写具体意见后退回，但不可转交。所有写入必须绑定当前 Attempt 与节点版本，决定还必须绑定 Instance 版本。参与者不能借任务接口读取完整协作者实例。
16. 员工可以在工作台填写目标、可选背景和可选协作者来请求候选流程。请求必须先耐久落库并由不持有飞书凭据的中央 Worker 生成，候选必须通过既有 DAG 确定性校验并只保存为草稿。含 Agent 的候选必须以明确接受或退回的 Human 决策节点结束，`reject_target` 必须是该节点的直接上游 Agent，确保退回意见可以进入正确返工 Attempt；纯 Human 流程仍可使用普通待办。浏览器不得模拟机器人消息、声明可信 Owner 或直接启动流程；重复提交、Worker 接管、失败重试和终态必须可审计。用户仍需在草稿预览中独立确认后才启动。
17. Instance Owner 可以在受控 DAG 画板拖动节点形成个人布局，或对未来区域发起节点增删改和节点返工。布局不得改变领域状态；结构修改必须先创建耐久 GraphEditPreview，再由同一当前 Owner 显式确认；返工必须复用 RestartPreview。冻结线、非法 DAG、陈旧版本、非 Owner 和客户端伪造影响集合均应被服务端拒绝。
18. 每个新建或生成节点都有用户可读的交付物合同。普通 Human、Agent 和 Tool 的完成结果缺少必填字段时不得写入 Attempt 或解锁下游；可选字段为空不得造成误拒绝；身份、Attempt、版本和 claim 校验仍先于内容校验。
19. 需要结构化交付物的飞书 Task 不能通过原生完成状态推进中央节点。用户点击任务中的工作台链接后，应直接打开本人当前待办表单；已处理、已转交或无权访问时显示安全的统一提示。
20. 自然语言旅游规划候选必须先收集出发地、日期、人数和预算，把景点与交通等独立公开信息研究拆成显式 `web.search` Tool 节点，再由汇总 Agent 同时消费已确认需求与全部研究交付物，最后由 Human 明确接受或退回。每个研究节点必须保存正文和来源 URL；无来源结果不能完成。联网研究未由部署显式开启时，服务必须拒绝生成依赖实时外部事实的旅游流程，不能退化成浅流程或让普通 Agent 冒充已联网搜索。
21. 没有权限访问某份企业资料或项目上传件的 actor、节点或 Attempt，检索结果、引用、摘要和错误信息都不得泄露其存在。授权必须发生在检索正文之前，不能依赖模型过滤。
22. PlannerRuntime 与 AgentRuntime 不得持有 PostgreSQL 写权限、飞书应用凭据、租户级对象存储密钥或生产密钥。伪造、过期或跨 Instance 的能力信封必须 fail closed，并留下不含敏感正文的审计。
23. 同一输入、上下文、只读工具和校验器下，Pi 或 DSH 适配器必须以首次硬校验通过率、用户改图次数、遗漏输入、无效依赖、节点冗余、一次接受率、耗时和成本与 Python 基线对照。没有材料改善，或需要破坏运行时边界时，不采用该适配器。
24. 项目工作区首版由单个 Instance 加项目上传件承载。前五个真实项目中若至少两个需要多个独立 DAG 共享同一批资料，必须重新评估独立 Project 聚合，不能继续把语义塞入 Instance 元数据。

## 8. 关键假设与未验证事项

首个行业与场景、真实使用频率、相对飞书原生方案的收益、模板维护意愿和付费意愿均未知。它们不会被本轮功能设计或 legacy 测试替代。

当前还有四个会改变架构的关键假设：企业能否维护明确的全员共享资料集；单个 Instance 是否足以承载首批项目；组织是否允许选定数据进入批准的云模型；可替换 Runtime 是否比当前有界 Python 基线带来可测改善。它们分别用共享语料发布审计、前五个真实项目、模型外发政策门禁和同合同 A/B 验证，不能用框架功能演示替代。

Edge 的采用、组织数据政策、设备管理成本和云端不可替代性仍未验证。Proof 测试通过不等于这些假设成立，当前选择是暂停而不是继续补齐分发能力。
