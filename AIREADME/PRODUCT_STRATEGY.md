# PRODUCT STRATEGY · larkflow

> 状态：Target Draft · 2026-07-30

## 1. Vision

让企业中的每个跨人协作目标，都能被可靠地分解、承接、执行和验收；组织流程既不会因个人电脑离线而中断，也不会因为使用 AI 而失去人的责任边界。

## 2. Market Segments & Jobs to Be Done

### 首要用户

- 50–1000 人、已深度使用飞书、跨部门协作频繁的企业。
- 业务、交付、法务、财务、研发运营等需要重复协调多个责任人的流程 Owner。
- 希望让员工使用个人 Agent，但又需要统一知识、能力、权限和审计的 IT / AI 管理者。

### 核心 JTBD

- 当我发起一个跨团队目标时，帮我沿用组织认可的流程，找到正确责任人，并持续获得可信进度。
- 当我接到工作包时，让我决定自己做、让个人 Agent 做，或在授权范围内组织下属继续拆解。
- 当流程卡住、返工或跨部门踢皮球时，保留责任边界和证据，把问题升级给正确的人。
- 当流程反复发生时，把一次成功实践沉淀为可治理、可复用的企业模板。

## 3. Relative Costs

用户当前付出的成本包括人工拆任务、找人、催办、同步上下文、追文档版本和复盘责任。引入 larkflow 的新成本是企业授权、角色绑定、模板校准和行为改变。

产品必须复用飞书原语降低迁移成本；入驻采用小范围授权和渐进发现，不能要求企业先整理全部知识。任何自动生成的流程都必须由流程 Owner 确认后发布。

## 4. Value Proposition

- **对发起人：** 从群聊催办升级为跨责任边界的可视化承诺、交付和验收。
- **对责任人：** 待办属于自己，执行方式由自己选择；个人 Agent 是助手，不是另一个被管理对象。
- **对部门主管：** 可以把上层工作包展开为本部门 DAG，同时保护内部人员和细节权限。
- **对企业：** 把知识、Skill、MCP、模板和审计集中治理，让不同员工的本地 Agent 获得一致且最小化授权的能力。

相对飞书原生任务/审批，larkflow 的差异不是“也能派待办”，而是**可复用的多层 DAG、父子工作契约、动态角色解析、跨部门验收和个人 Agent 协同**。

## 5. Trade-offs

- 选择飞书原生，不做跨办公套件的广覆盖。
- 选择人类最终责任，不做 Agent 直接领走企业待办。
- 选择最多三级和显式父子契约，不做无限递归或父层穿透管理。
- 选择发布模板 + 受控实例变更，不把每次自然语言生成都当生产流程。
- 选择渐进入驻和人工校准，不宣称自动理解企业全部知识。
- 选择业务 DAG 独立于 LangGraph，牺牲单一框架的开发便利，换取可迁移的产品模型。

## 6. Key Metrics

**North Star：** 每月被验收的跨责任边界工作流实例数。有效实例至少包含两个不同人类责任人和一个明确验收点。

MVP 同时观察：

- 工作包从创建到责任人确认的中位时长。
- 按模板启动且无需重建结构即可完成的实例占比。
- 阻塞被识别到升级或处理的中位时长。
- 人工催办次数、线下状态同步时间相对基线的下降。
- 个人 Agent 执行的工作包中，成功提交且由责任人确认的比例。
- 权限越界、无责任人节点和不可审计状态变更必须为 0。

## 7. Growth

落地路径是“一个高频流程 → 一个部门模板库 → 跨部门模板 → 企业过程地图”。每次完成、打回和改派都会产生模板改进证据；已验证的企业模板可以在脱敏后沉淀为行业模板，再通过 Fork 带回企业。

增长依赖模板复用和组织扩散，不依赖员工单独安装一个个人效率工具。

## 8. Capabilities

必须形成的核心能力：

1. 多租户组织、人员、角色与权限模型。
2. 四级模板库、不可变版本、Fork、发布审核和合规锁。
3. 最多三级的实例编排、父子工作契约、验收、Attempt 和审计。
4. 飞书任务、消息、文档、云盘和通讯录的可靠投影与对账。
5. 本地 lark-cli / Agent 注册、离在线状态、任务领取、结果回传和安全升级。
6. 企业知识、Skill、MCP 注册表，以及短时、最小权限的 Capability Lease。
7. 渐进式企业过程发现、候选 DAG 生成和人工校准。

## 9. Defensibility: Can’t / Won’t

飞书原生任务、审批和自动化可以覆盖单层派单，但通常不会替企业维护跨部门的递归工作契约，也不会天然协调不同厂商的个人 Agent。单机 Agent 能执行任务，却无法在设备离线时承担企业责任、组织权限和跨人审计。

larkflow 的防御性来自企业模板图谱、角色解析历史、真实运行与返工数据、能力治理和飞书深度集成的组合，而不是 DAG 画布或某个模型 API。

## 关键假设与低成本实验

| 假设 | 低成本实验 | 继续条件 |
|---|---|---|
| 企业存在高频跨责任边界流程 | 访谈 5 家飞书企业，回溯最近 30 天实例 | 至少 3 家各有每月 ≥10 次同类流程 |
| 主管愿意维护模板 | 用 YAML/白板共创 3 个模板并二次复用 | 2 个模板在无产品人员介入下再次启动 |
| 三级足够表达 MVP | 对 10 个真实流程做层级映射 | ≥80% 可在 3 层内表达 |
| 人愿意让 Agent 执行但保留责任 | 用假门/人工 concierge 模拟执行方式选择 | ≥30% 合适工作包选择 Agent，且责任人认可 |
| 相比飞书原生有显著增益 | 用任务 + 审批 + 文档复刻同一流程对照 | 催办或状态同步时间下降 ≥30% |
