# CORE · larkflow（飞流）

## 身份
飞书原生的 AI 工作流编排引擎。用户在飞书里一句话发起一件事，larkflow 把它编排成一条能跑的流程（一张任务依赖图），AI 节点自动干、human 节点派给人，过评分门禁后逐步推进，全程落在飞书里。

## 使命
把「团队 / 组长在飞书上反复手工派活、追进度、催办、汇总收口」的协调劳动，变成可追踪、可复用、有质量门的自动化工作流。

## 用户
先 Maxwell 自己 + 其带的团队（dogfood）。形态 = 飞书企业自建应用，挂工作台。开发在独立 dev 飞书租户（clean-room，ADR-008）。

## Non-Goals（明确不做）
- 不做通用 iPaaS / Zapier 式集成平台（只做飞书原生的编排）。
- MVP 前端 = 飞书卡片（cards-only）：app + bot + 交互卡片 + 任务，**不建小程序 / H5 面板**（延后，ADR-011）。
- 不做纯 DAG 无环编排（要打回 / 循环，用 LangGraph 的环）。
- 不对 C 端收费、不做独立 SaaS 门户（团队内部工具优先）。

## 绝不（硬约束红线）
- **单一事实源不破**：实例运行态由 LangGraph checkpointer 持有，是权威；飞书任务 / 多维表格 / 文档只是投影，绝不反向当真相源写回。
- **key / 凭证不入库**：飞书 app secret、newapi key、lark-cli token 走 env / keychain，绝不落 git、绝不进任何 AIREADME 文件。
- **LLM 只走 newapi 网关**，不直连厂商 SDK。
- **clean-room**：只借公开的架构范式，不复制任何雇主代码 / 业务数据 / 内部命名。
