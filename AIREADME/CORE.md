# CORE · larkflow（飞流）

> 状态：Target · 既有设计简化版 · 2026-08-01

## 身份

larkflow 是基于飞书的企业协作 DAG 系统。它把一个多人协作目标拆成有依赖、有唯一责任人、可验收和可追溯的节点。飞书承载消息、任务、文档和组织身份；larkflow 负责模板、实例、调度、变更、重做和审计。

当前设计不是从零重建。它沿用既有产品设计，并围绕最小闭环做减法。合同、招聘等内容只是示例，不是产品定位。

## 使命

让企业已有的多人流程从“靠人记、靠群催、靠经验恢复”变成可以明确启动、持续推进、受控修改和可靠复盘的协作实例。AI 和工具可以执行节点，但责任仍归属于人。

## 当前用户

- 项目 Owner：创建或确认实例，查看进度，处理暂停、取消和重启。
- 节点 Owner：接收飞书责任入口，完成 Human 节点，或接管 Agent、Tool 节点的异常。
- 流程管理员：维护模板、版本、启停和简单锁定规则。

## 产品不变量

1. 每个节点必须有唯一人类 Owner，`human / agent / tool` 只表示执行方式。
2. 实例先进入 `draft`，只有人明确确认后才能运行；草稿可以丢弃。
3. 模板可选。实例可以从启用模板创建，也可以从结构化无模板草稿创建。
4. 模板版本不可变，实例保存完整图快照；MVP 的锁只使用版本级布尔 `locked`。
5. 运行中编辑只影响未开始区域，并经过预览、确认和 `graph_revision` 校验。
6. 节点重启会重置目标节点和所有可达下游；历史通过新的 Attempt 保留，DAG 不画回边。
7. 中央数据库是业务真相源，飞书是交互入口和可恢复投影。
8. 权限、责任、状态转换和图修改合法性由服务端计算，不信任卡片或执行器回传的身份。
9. LangGraph 只可作为单个复杂 Agent 节点的可选内部运行时，不承载跨人流程的唯一状态。

## 当前 MVP 不做什么

- 不建设独立 Project、IM、搜索、知识库和应用市场全套平台。
- 不实现模板子 DAG、临时子 DAG或三级下钻。
- 不实现个人 Agent Edge、设备注册或 Capability Lease。
- 不建设 Knowledge、Skill、MCP 注册表或 RAG 模板匹配。
- 不引入 Kafka、微服务拆分、字段级锁、复杂 ACL 或完整图形化编辑器。
- 不把五维百分制评分作为首版质量模型。
- 不声称市场需求、频率、降本或付费意愿已经得到验证。

## 当前阶段

当前阶段是既有设计的简化与一致性核验。设计取舍见 [`research/design-simplification.md`](../research/design-simplification.md)。仓库中的 LangGraph + SQLite + lark-cli 代码仍是 legacy 机制原型，不是上述目标架构的已实现版本。
